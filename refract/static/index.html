Local fixtures

Guided demo

One run through the hard cases: identical bytes from two sources, a recall that must not affect the other source, and a server restart underneath an in-flight download. Every step calls the same API the buttons above use.

  1. 1
    Duplicate delivery

    Same fixture → Atlas Registry and Harbor Exchange. Expect one physical blob, two deliveries, two receipts.

  2. 2
    Recall one source

    Recall Harbor only. Its downloads stop; Atlas keeps serving the same bytes; cleanup stays blocked by Atlas.

  3. 3
    Restart during download

    Open a slow Atlas download, restart the server mid-stream. The lease is abandoned, cleanup may proceed once references end, and the reader fails closed.

  4. 4
    Cleanup gate

    End Atlas retention, purge when nothing holds the bytes, then receive the same fixture again: the blob is resurrected with a fresh delivery.
